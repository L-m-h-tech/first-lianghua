〇、核心结论（先看这 5 条）

  1. 定位决定差距，不是“做得差”。一个完整量化系统的行业标准是 数据→因子→策略研究→回测→组合→风控→执行→绩效→监控→工程 十层。本项目在前 6 层与第 9 层已经达到个人项目里罕见、部分超过开源框架开箱水平的程度；唯一结构性塌陷是第 7 层“订单执行”——信号止于“建议”，没有纸面/模拟账户，更没有实盘闭环。这是与 vnpy / freqtrade / Lean / nautilus 的最大差异。
  2. 本轮最该补的一件事：零依赖“纸面交易引擎”（G1）。freqtrade 的 dry-run、vnpy 的 SimNow 都是“回测→实盘”之间的必经中间态。本项目有历史回测、有实时信号、有共享资金池，唯独缺“实时行情下虚拟成交、跑出一条含成本的模拟净值曲线”。它不触碰任何合规红线，却能第一次回答“综合分真照做，账户会怎样”。
  3. 第二件事是把“严谨性短板”补齐：日线回测目前是“信号当日收盘价成交”（backtest.py L289，已在报告口径诚实声明，属温和乐观而非隐瞒 bug），缺 next-bar 保守成交对照、蒙特卡洛置信区间、回测结果留档（G4）。这正是 awesome-backtesting、freqtrade lookahead-analysis 反复强调的头号陷阱。
  4. 工程上有个零成本、高收益的欠账：项目至今不是 git 仓库（G9）。191 个测试用例已经很扎实，却没有版本历史、无法一键回滚——与测试纪律不匹配，建议立即补上；同时配置外置（G10）、数据源自动熔断降级链（G11）、数据质量监控（G6）一起把“数据/工程底座”补齐。
  5. 有些“差距”是已经裁决过不要做的，不要被开源热度带偏：L2 逐笔回放、DRL 实盘、端到端 LLM 决策、Rust/纳秒高频内核、生产环境引入重依赖、直接 CTP 自动下单——这些在本项目场景下要么免费数据不可得、要么有反面证据、要么有法定合规门槛（证监会 2025 年第 12 号公告：程序化交易须报告 + 穿透式测试）。第六节给出完整“不做”清单与理由。
三条不可违背的总原则（沿用《统一改进路线图》，本报告所有方案都在此约束下）：① 生产运行链路零新增第三方依赖（仅 requests / uiautomation / websocket-client；pandas、sklearn 等只许出现在 tools/ 研究侧；GitHub 算法只读源码、用标准库重写）；② 确定不更差才采纳（默认不改现有输出、先影子模式、可一键回退，策略/ML 必须样本外真实成本后不劣于现状才上线）；③ 每处改动配零网络合成断言 + 真实 main.py --once --no-launch 冒烟，负结果诚实呈现，不编造数据。

一、一个完整量化交易系统的标准组成（十层）

综合 vnpy 分层、Qlib 四层工作流、QuantConnect Lean、apexphere/quant-trading 六层模型、技术栈“回测到实盘四层方案”及极客时间模块论，收敛为以下十层——这是本次对标的统一坐标系。
层职责行业标准构件 / 关键词
1 数据层多源采集（tick/分钟/日线、历史+实时）、清洗校验、存储、数据质量主备源降级、PIT(point-in-time)数据、时序/列式存储(Parquet/DuckDB/ClickHouse)、缺失率/schema 监控
2 因子/信号层把原始数据变成方向/强度信号技术指标、基本面、另类/舆情、时序+横截面因子、因子 IC/ICIR/衰减评估、因子库注册
3 策略研究层组织信号成可复用策略、选参、防过拟合策略模板/插件化、网格/贝叶斯超参寻优、Walk-forward、PBO/DSR、前视偏差自动检测
4 回测引擎历史上尽量真实地重演交易事件驱动逐 bar / 向量化、next-bar 成交、bid/ask、滑点冲击模型、手续费/平今/保证金、组合回测
5 组合/仓位层把多个信号变成具体手数与资金分配sizing、多策略/多品种资金分配、相关性与风险预算、敞口/集中度、调仓再平衡、强平
6 风险控制层独立于策略的事前/事中/事后闸门委托流控/撤单上限/自成交、实时风险度、单日亏损熔断、压力测试、VaR/CVaR
7 订单执行层把目标仓位变成真实/模拟委托与成交OMS 订单管理、交易网关(CTP 等)、TWAP/VWAP/冰山算法单、纸面(dry-run/SimNow)、实盘合规
8 绩效分析层公平裁判策略与各环节Sharpe/Sortino/Calmar/Omega、最大回撤/修复时长、VaR、胜率盈亏比、归因、月度热力、tear sheet
9 监控/交互层人看得懂、离得开、被及时通知图表看板、Web/移动端、多渠道告警、心跳看门狗、日志轮转、AI 解读/追问
10 工程基建层可维护、可复现、可恢复git 版本、配置外置/.env、依赖锁定、测试/CI、容器/任务计划部署、备份与灾备、文档/CHANGELOG

五、逐项修改方案（文件级改法 + 验收，全部遵守三铁律）

P0G9 ｜ git 工程化（立即，约半天）
现状事实
实测项目根无 .git；requirements 仅写 >=；23 轮迭代全靠文件覆盖，没有版本历史与回滚点，与 191 个测试的严谨度不匹配。
修改方案
① git init 后首个 tag 记录“第23轮基线”；② 写 .gitignore：忽略 __pycache__/、*.pyc、data/*.db、cache/、logs/、reports/*.html/*.txt/chart_data.js（产物，可再生）与 reports/assets/（同步副本），保留 data 下 csv 配置表与全部源码/测试/文档；③ 用 D:\Python\python.exe -m pip freeze 把三个直接依赖锁成 == 当前版本；④ 新增 CHANGELOG.md 按轮次倒序记录、VERSION（如 0.23.0）。
验收
git status 干净、被忽略产物不进库；锁定后在干净目录 D:\Python\python.exe -m pytest 仍为权威 191 全绿。零生产代码改动、零风险。
P1 · 最高价值G1 ｜ 纸面交易引擎 PaperBroker（补执行层塌陷）
现状事实
信号链路止于 analyzer 综合分与“建议手数”；signal_outcomes 只判固定周期（30m/2h/次日）方向对错，不含手续费、不含仓位、没有连续资金曲线；portfolio 共享资金池只对“当前建议”做静态盯市，不会把历史信号串成一笔笔虚拟成交。
对标
freqtrade 的 dry-run 用 sqlite 持久化虚拟订单/持仓/成交，在实时行情下不花真钱跑完整机器人；vnpy 接 SimNow 仿真。二者都是回测与实盘之间不可跳过的一环。
修改方案（纯标准库，默认只新增不改旧输出）
  1. 新增 paper_broker.py：PaperBroker 每轮吃 analyzer 结果 + 最新 quotes，把“跨档/反手信号”转为虚拟委托；成交模型两档：close（信号轮收盘价，与现回测口径一致）与 next（下一轮首个新价成交，保守、推荐为影子默认），锁板复用 backtest 的判定跳过/顺延；手续费直接读 data/futures_fees.csv、滑点复用 BACKTEST_SLIP_RATE。
  2. 仓位/盯市/强平复用 portfolio.py 现有逻辑（三种 sizing、板块约束、强平状态机），不重写第二套。
  3. storage 新增 paper_orders / paper_trades / paper_equity 三表（订单、成交、每轮净值）。
  4. reports 新增 paper_account.txt（虚拟净值/持仓/已实现+浮动盈亏/胜率/回撤）与图表看板一张净值图；config.PAPER_ENABLED 开关，默认开启影子但独立成段，不动现有任何输出。
它回答什么
第一次能量化回答：“如果严格按综合分+资金管理做，含真实成本后的账户净值、最大回撤、换手与信号 hit 率是否一致”——这是判断整套规则能不能走向实盘的证据链起点。
验收
零网络合成断言（开仓/加仓/反手/锁板跳过/手续费双边/强平/next 成交严格晚于信号）；真实 --once --no-launch 冒烟；连续影子 ≥4 周后与 signal_outcomes 对照，若成本后为负必须诚实呈现并回退，不粉饰。
P1G4 ｜ 回测严谨性：next-bar 对照 + 蒙特卡洛 + 结果留档
现状事实
backtest.py L280-292 在第 i 根用截至 i 的数据出信号、entry_price=closes[i] 同根收盘成交。实盘“看到收盘价的瞬间已无法以该收盘价成交”，属温和的时点乐观；报告头已诚实声明口径，不是隐瞒的 bug，但缺少更保守的对照模型。另外单次结果覆盖写、无置信区间，容易“挑一次最好的”。
修改方案
① prepare 阶段保留 open，新增 --fill {close,next_open}：按铁律②，先两种并列输出（现 close 为默认保持可比，next_open 为保守对照），影子对比一轮、确认 next_open 不更差后再考虑切换默认；② 标准库 random（固定种子可复现）对交易序列做 1000 次 bootstrap 重排，给出累计收益/最大回撤的 5%–95% 区间；③ storage 新增 backtest_runs 表（时间戳、全部参数、核心指标、样本量），每次跑都留档，报告里自动带上“历史第几次、是否优于多数历史参数”；④ 报告抬头自动引用 tools/backtest_validation 的 DSR/PBO 结论。
验收
构造已知序列断言 next_open 成交日严格 = 信号日 +1 交易日；bootstrap 区间包含确定性净值；历史回测可在表里列出多次记录对比。
