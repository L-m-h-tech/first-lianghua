# 云服务器并行采集部署说明（第120轮 · 动态服务器数量版）

> 本方案**不修改主项目任何代码**：全部逻辑在 `tools/` 下独立运行，
> 主代码（config.py / futures_data.py / main.py 等）零改动。
> 数据写入与主程序共用的 `data/monitor.db`（minute_bars 表，UNIQUE 去重，无冲突）。

## 一、目标与原理

- **目标**：320 个分钟K任务（64 品种 x 5 周期）快速完成且不被新浪封锁（服务器越多越快，最多 10 台）。
- **原理**：新浪封锁的是"单 IP 高频请求"；N 个独立 IP = N 倍吞吐，各自都在安全线内。
- **动态适应（v2）**：服务器上限 10 台，实际几台在线就用几台分摊——少台时任务分到更少服务器上继续跑（慢一点但不中断），
  掉线/被封的服务器自动剔除，任务自动换到其他台重试。
- 每台间隔 0.7s/请求（86 次/min，实测封禁阈值 133 次/min，仍有余量）。
- 本机 IP 完全不碰新浪 stock2，**本机永远安全**。

## 二、按量计费成本分析

### 2.1 计费方式对比

| 方式 | 价格（参考阿里云/腾讯云） | 适合场景 |
|---|---|---|
| **按量计费（秒级）** | 1核1G 约 0.06~0.15 元/小时 | 交易时段开着、休盘销毁，**本方案推荐** |
| **抢占式实例** | 比按量再便宜 50%~80% | 可被回收，采集可容忍重试时用 |
| 包年包月 | 30~50 元/月/台 | 7x24 常驻才划算 |
| 新用户券 | 常送几百元券 | 首次验证基本免费 |

### 2.2 实际开销估算（按量 x 动态台数）

| 用法 | 单台小时价 | 每天开机时长 | 10 台/天 | 22 交易日/月 |
|---|---|---|---|---|
| 仅交易时段（约 6.5h） | 0.10 元/h | 6.5h | **约 6.5 元** | **约 143 元** |
| 8 小时（含回填+增量） | 0.10 元/h | 8h | 约 8 元 | 约 176 元 |
| 常驻 24h（不推荐） | 0.10 元/h | 24h | 约 24 元 | 约 528 元 |

**结论：10 台全开一个月约 143~176 元；实际台数浮动时费用随台数线性变化（每台约 14 元/月），用几台花几台的钱。**
新用户券/试用金基本能覆盖首月验证。

### 2.3 省钱要点

1. **只在交易时段开机**：9:00-11:30 / 13:30-15:00 / 21:00-次日 02:30，其余时间销毁
2. **用完即销毁**：按量实例空闲也计费，不要在控制台留着常驻
3. **抢占式实例**：采集失败可重试，用抢占式再省一半
4. **带宽选小**：1Mbps 出网带宽足够，别选贵的独享带宽
5. **快照别乱开**：别开自动快照，导出一次数据即可

| 文件 | 位置 | 作用 |
|---|---|---|
| `tools/sina_proxy_server.py` | **每台服务器**各一份 | HTTP 采集代理（零依赖，纯 Python 标准库） |

## 四、服务器端部署（每台都要做）

1. 云控制台创建 N 台实例（按量计费，1核1G，Linux），最多 10 台，先开几台都行
2. 每台装 Python 3（Ubuntu：`sudo apt install python3`）
3. 上传 `tools/sina_proxy_server.py` 到每台（如 `/root/sina_proxy_server.py`）
4. 每台启动：
   ```bash
   nohup python3 /root/sina_proxy_server.py --port 9001 --gap 0.7 > server.log 2>&1 &
   ```
5. **安全组放行 9001 端口**（控制台 -> 安全组 -> 入方向 -> TCP 9001）
6. 本机验证：
   ```bash
   curl "http://<服务器IP>:9001/health"        # 应返回 {"status":"ok",...}
   curl "http://<服务器IP>:9001/daily?symbol=RB0" | head -c 200
   ```

编辑 `tools/server_collect.py` 底部 `SERVERS`，填入全部候选服务器地址（最多 10 台，先开几台填几台）：

SERVERS = [

## 七、速度与扩容（要更快就加服务器）

总耗时公式（每台间隔 0.7s）：**总耗时 = 3.8 / 服务器数（分钟）**

| 在线服务器数 | 耗时 | 每台任务 | 每台频率 | 是否安全 |
|---|---|---|---|---|
| 3 | ~1.3 分钟 | 107 任务 | 86/min | 有余量 |
| 5 | ~46 秒 | 64 任务 | 86/min | 有余量 |
| **10（上限）** | **~23 秒** | 32 任务 | 64/min | 很安全 |
| 中途掉 1 台 | 任务自动换台重试，整体略慢 | 其余台分摊 | 86/min | 不中断 |

**加服务器严格线性提速**：新浪按 IP 独立计数，N 台 = N 倍吞吐，互不影响。
**动态适应**：在线台数变化无需改代码——掉线自动剔除、任务自动换台重试，少台慢一点但不停摆。

推荐 `--gap 0.7`（每台 86次/min，仍有余量）；想更保守调回 0.9s（48秒）；
更激进用 0.6s（每台 100次/min，余量 1.3 倍，需观察日志确认不封）。

## 八、容错与故障处理

> `server_collect.py` v2：启动自动探测在线服务器；任务失败自动换下一台在线重试；
> 某台 456 / 连续失败自动剔除，其余台继续分摊。

| 故障 | 现象 | 处理 |
|---|---|---|
| 某台被封（456） | 该台自动剔除，任务换其他台 | 重启实例换新 IP（调度器下次自动恢复使用） |
| 某台超时 | fail 增加、耗时变长 | `curl http://IP:9001/health` 确认存活 |
| 某台挂掉 | 自动剔除，任务换台重试 | 控制台重启实例；重启后自动回到在线列表 |
| 全部失败 | 调度器报"无在线服务器" | 检查安全组 9001 是否放行、服务器能否访问新浪 |

> v2 已内置失败自动换台重试 + 掉线剔除，无需额外配置。

## 九、验证不被封

每轮跑完，在**每台服务器**上执行：
```bash
curl "https://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20t=/InnerFuturesNewService.getDailyKLine?symbol=RB0" \
  -H "Referer: https://finance.sina.com.cn/" -H "User-Agent: Mozilla/5.0" -o /dev/null -w "%{http_code}\n"
```
- `200` = 没被封 OK
- `456` = 被新浪拦截（重启实例换 IP 或调大 gap）

本机调度器输出 `失败=0` 即在线服务器全部成功。

## 十、与主项目的关系（明确边界）

1. **主代码零改动**：不 import 服务器工具、不改 fetch 链路、不改任何配置。
2. 调度器把数据写进 `data/monitor.db` 的 `minute_bars` 表，主程序读库即得。
3. 主程序自己的 `collect_minute_bars` 可继续跑（双保险）或停用，
   两者写同库有 UNIQUE 去重，不会重复。
4. 不想用服务器方案时，删掉 `tools/` 下 3 个文件即可，主程序不受影响。

## 十一、systemd 自启（可选，推荐）

```ini
# /etc/systemd/system/sina_proxy.service
[Unit]
Description=Sina stock2 proxy
After=network.target
[Service]
ExecStart=/usr/bin/python3 /root/sina_proxy_server.py --port 9001 --gap 0.7
Restart=always
[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl enable --now sina_proxy
```
